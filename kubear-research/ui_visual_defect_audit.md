# Kubear UI and Visual Defect Audit

## Audit Scope

The review covered the homepage, How it works, Your money view, EMI calculator, Learn hub and Privacy page at desktop width. Fresh route loads produced successful analytics responses and the development status reports no current TypeScript errors. A previously logged import-resolution error predates the current bundle and is not reproduced by the active project state.

| Area | Observed weakness | Remediation decision |
|---|---|---|
| Home visual rhythm | Several sections use similar large dark or still-life image modules. The visual distinction between a money moment and its functional purpose is weak. | Replace repeated scene treatment with differentiated HTML/CSS money instruments: allocation, cadence, timeline, split and control state. |
| Decorative diagrams | The calculator dial/grid and several hero grids look like financial charts but do not communicate a data relationship. | Retire decorative graph language and use directly meaningful diagrams with plain labels, illustrative state and clear relationships. |
| Product value | The product’s unified money view appears later than the emotional campaign narrative. | Make an information-rich “money picture” a first-screen companion and repeat it in progressively deeper forms. |
| Layout density | Some desktop sections have very large image or colour blocks with comparatively low explanatory information. | Improve information hierarchy with compact ledger instruments, purposeful annotation and strong comparison layouts. |
| Shared UI | Header, cards and visual surfaces are stylistically close, but section modules do not always share a predictable component anatomy. | Standardise shared instrument shells, annotations, action bars, focus states and responsive rails. |
| Tools | Calculator logic and core form layout appear functional, but the visual treatment is too abstract for a planning tool. | Replace decorative tool graphics with contribution/payment/runway explanations tied to live input state. |
| Learn and support routes | They contain good content but need the same functional visual vocabulary as the main promise. | Apply shared visual primitives to heading areas, topic rails, featured content and trust explanations. |

## Implementation Guardrails

All revised scenes will use illustrative values only, labelled as examples. No live bank data, third-party logos, product screenshots, financial advice or return promises will be added. The current conversion destinations, static SEO route architecture, calculator formula module and no-production-deployment condition remain unchanged.
